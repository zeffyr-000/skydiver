# Design System — Skydiver

Skydiver has **no UI framework theme** (no Angular Material). The look is a small, bespoke
**8/16-bit pixel-art** system: a limited palette, chunky bevelled borders, bitmap fonts, and a
handful of reusable components. This document is the reference for it.

Theme: early-1900s aerobatics at golden hour — sepia map paper, Sopwith-biplane red, brass
instruments, a dithered sunset sky over silhouetted hills.

## Principles

- **No image assets for chrome.** Borders/bevels are drawn with multi-layer **zero-blur**
  `box-shadow`s, so they stay crisp at any zoom/resolution.
- **Square corners.** `--radius: 0`, always. Pixel art never rounds.
- **Tokens over literals.** Components reference CSS custom properties; never hardcode a colour or
  a spacing value.
- **Accessibility via Angular Aria.** Interactive widgets use `@angular/aria` primitives for roles,
  focus and keyboard behaviour.
- **Every control clicks.** Moving through a menu ticks, pressing a button chimes — the kit asks
  for sounds through a token and never knows how they're made (see [UI sounds](#ui-sounds--the-ui_sounds-token)).
- **Motion is optional.** Every animation must leave a correct screen when it is cut to its end
  state (see [Motion](#motion--data-motion)), and a gamepad must be able to reach every control:
  real focusable elements, laid out so "the nearest one that way" is the right one.

### Spacing (4px grid)

`--px: 4px`, `--sp-1: 4px`, `--sp-2: 8px`, `--sp-3: 12px`, `--sp-4: 16px`, `--sp-6: 24px`,
`--sp-8: 32px`.

### Borders & type

- `--border-w: 4px` (chunky pixel border), `--radius: 0`
- Fonts: `--font-head: 'Silkscreen'` (headings, labels, buttons — regular 400 and bold 700) and
  `--font-body: 'Departure Mono'` (running text), self-hosted in `public/assets/fonts/` (both OFL).
  They are **true bitmap faces: only crisp at whole multiples of their pixel grid**, so sizes come
  from the tokens and nothing else:
  - `--fs-head: 16px` (Silkscreen ×2 — labels, buttons, bars), `--fs-h3: 24px` (×3 — menu
    items, card titles), `--fs-h2: 32px` (×4), `--fs-h1: 48px` (×6)
  - `--fs-body: 22px` (Departure Mono ×2 — every paragraph, row and value in text)
  - Never set an arbitrary `font-size` on these faces (an 18px or 20px Silkscreen smears).
  - The game canvas HUD uses **Departure Mono only** (11 px, 22 px for banners): it is
    thresholded to hard pixels, and Silkscreen's half-pixel diagonals turn M/N/W into "II" there.
  The game HUD uses the same faces, rasterised at native size into the canvas (`engine/font.ts`).
- Layers: `--z-overlay: 1000`, `--z-modal: 1100`, `--z-wipe: 1200` (route-transition wipe)

## Surface mixins

From [`src/styles/_pixel-ui.scss`](../src/styles/_pixel-ui.scss):

```scss
@include pixel-bevel($w, $hi, $lo); // raised: light top-left, dark bottom-right, hard outline
@include pixel-inset($w, $hi, $lo); // sunken/pressed: light source flipped
```

Both default to `--border-w`, `--highlight`, `--shadow`. Use `pixel-bevel` for panels/buttons at
rest and `pixel-inset` for pressed/active or recessed wells.

```scss
.my-panel {
  background: var(--parchment);
  padding: var(--sp-4);
  @include pixel-bevel();
}
```

> The renderer (`engine/renderer.ts`) mirrors a few of these hex values in a local `COLORS` map
> because a `<canvas>` can't cheaply read CSS variables per frame. **If you change a palette
> token used in-game, update that map too.**

## Sprite crops (decorative pixel art in the UI)

The "no image assets" rule applies to *chrome* (borders, bevels). Decorative pixel art — the logo,
medals — reuses the sprite sheets generated by `tools/generate-sprites.mjs` into
`public/assets/sprites/`. [`_sprites.scss`](../src/styles/_sprites.scss) crops one frame from a
horizontal strip with a fixed-size box + `background-position` at an integer scale:

```scss
@use 'sprites' as spr;
.hall__medal--gold { @include spr.medal(0); }    // medals.png frame 0
.title__logo-ch { @include spr.sheet-frame('assets/sprites/logo.png', 24px, 26px, 8, 0, 3); }
```

Frame sizes/counts are duplicated in that partial on purpose: the UI never imports the game
engine's sprite metadata.

Flat sheets from `tools/generate-sprites.mjs`: `paper.png` (parchment grain on panels/dialogs), `logo.png` (the SKYDIVER logotype, one letter per frame — five-band metal ramp,
ink outline and drop shadow baked by `tools/generate-sprites.mjs`), and `rivet.png` (brass corner
rivets pinned on `PixelPanel`).

**Hi-bit pass.** All sheets ship at **2x source resolution**: the generator upscales authored
grids then runs a directional shading pass (per-material light/dark ramps in its `SHADE` map) so
fills get 16-bit modelling instead of flat 8-bit colour. CSS crops treat `$scale: 1` as one
screen pixel per source pixel. (The game's sky, sun and hills used to be sheets too; they're now
painted procedurally at the canvas's resolution by `engine/horizon.ts`.)

## Voxel-baked sprites

In-game art is **pre-rendered from voxel models**, not hand-drawn per frame: one model gives
every angle the Mode 7 camera needs with the same light, scale and outline.

- **Tool:** `node tools/bake-voxels.mjs` (pure Node, ~11 s, deterministic). Models live in that
  file; the kit (primitives, renderer, sheet packing) in `tools/lib/voxel.mjs`. Output:
  `public/assets/sprites/baked/*.png` + the generated `src/app/features/game/engine/baked-sprites.ts`
  — never edit that file by hand, re-run the tool and commit both.
- **Modelling:** metres, x right / y forward / z up, origin at the object's anchor (its base on
  the ground; the harness for the canopy rig). Build with `box`, `ellipsoid`, `sphere`, `capsule`,
  `cylinderZ`, `carve`; a material can be a function of (x, y, z) for stripes and panels; thin
  rigging is `line()`. Keep the voxel size under 1 ÷ (ppm × `DENSITY`) so surface splats stay
  hole-free; a depth-aware pinhole fill closes the odd 1-px gap on oblique surfaces. Model thin
  shells (the canopy) as the space *between two surfaces* so their thickness holds everywhere —
  a horizontal-only thickness test leaves a near-flat crown hollow.
- **Look:** lit from the camera's upper-left-front, shading quantised onto per-material
  **golden-hour ramps** (cool violet shadows → warm amber highlights, anchored on the palette
  tokens) with a light ordered dither, darker creases where depth jumps, and a selective outline
  (each material's darkest tone mixed with ink).
- **Scale:** pick `ppm` (sheet pixels per metre, written for a 216-line canvas) near the size the
  sprite is usually seen at — heroes are dense (diver 14, canopy 10, plane 7), props 3.5–8 — and
  the tool multiplies it by `DENSITY` = 360/216 for the 640×360 game canvas, so in-game scaling
  stays close to 1:1 and every pixel reads the same size.
- **Layout:** frame = elevationRow × cols + yawStep × anim + animFrame; choose the yaw steps (1
  for round things, 8 for buildings, 16 for the plane) and elevations (e.g. 14°/38°/70° for
  props, negative ones for things seen from below like balloons).

## The UI kit (`src/app/ui/`)

Import from the barrel: `import { PixelButton, PixelPanel } from '../../ui';`

### `PixelButton` — `<app-pixel-button>`

| API | Type | Default | Notes |
|-----|------|---------|-------|
| `variant` (input) | `'default' \| 'primary' \| 'brass'` | `'default'` | visual emphasis |
| `disabled` (input) | `boolean` | `false` | suppresses `pressed` |
| `type` (input) | `'button' \| 'submit'` | `'button'` | |
| `ariaPressed` (input) | `boolean \| null` | `null` | toggle semantics for exclusive-option groups |
| `block` (input) | `boolean` | `false` | full-width, left-aligned card button (a list of choices with details, e.g. the Grand Tour's events) |
| `ariaLabel` (input) | `string \| null` | `null` | accessible name when the visible text isn't enough (e.g. a lone key cap in Settings) |
| `pressed` (output) | `void` | — | emitted on click when enabled (plays `UI_SOUNDS.select()`) |

```html
<app-pixel-button variant="brass" (pressed)="start()">{{ 'menu.play' | transloco }}</app-pixel-button>
```

### `PixelPanel` — `<app-pixel-panel>`

A bevelled parchment surface with an optional title bar.

| API | Type | Default |
|-----|------|---------|
| `heading` (input) | `string` | `''` (title bar hidden when empty) |

Project content as children: `<app-pixel-panel heading="…"> … </app-pixel-panel>`.

### `PixelSlider` — `<app-pixel-slider>`

| API | Type | Default |
|-----|------|---------|
| `value` (**model**, two-way) | `number` | `0` |
| `min` / `max` / `step` (input) | `number` | `0` / `100` / `1` |
| `ariaLabel` (input) | `string` | `''` |

```html
<app-pixel-slider [(value)]="settings.musicVolume" [ariaLabel]="'settings.music' | transloco" />
```

### `PixelDialog` — `<app-pixel-dialog>`

Wraps the native `<dialog>` (`showModal`/`close`) and keeps it in sync with a signal.

| API | Type | Notes |
|-----|------|-------|
| `open` (**model**, two-way) | `boolean` | drives `showModal()` / `close()` |
| `heading` (input) | `string` | |
| `wide` (input) | `boolean` | roomier layout for content-rich cards (briefing, results) |
| `closed` (output) | `void` | emitted on ESC, backdrop, or programmatic close |

Falls back to the `open` attribute where `showModal()` is missing (jsdom in unit tests).

### `CountUp` — `<app-count-up>`

An arcade score tally: the number ticks up from 0 to `value` after `delay` ms over `duration` ms
(instant under reduced motion).

```html
<app-count-up [value]="breakdown.accuracy" [delay]="260" />
```

### `PixelMenuList` — `<app-pixel-menu-list>`

Keyboard-navigable menu built on `@angular/aria` `Listbox`/`Option`. Behaves like a momentary
trigger (selection resets after each activation). Moving focus to another option plays
`UI_SOUNDS.move()`, activating one `UI_SOUNDS.select()`.

| API | Type | Notes |
|-----|------|-------|
| `items` (input, required) | `PixelMenuItem[]` | `{ value: string; label: string }` |
| `ariaLabel` (input) | `string` | |
| `animateIn` (input) | `boolean` | staggered entrance on first render (title screen) |
| `activate` (output) | `string` | the activated item's `value` (Enter / Space / click) |

```html
<app-pixel-menu-list [items]="menuItems()" (activate)="onSelect($event)" />
```

### Screen backdrop — `<app-world-backdrop>` (in `features/game/backdrop/`)

Not part of the kit (it runs the game engine), but every menu screen uses it as its first child:
a fixed, full-viewport, `aria-hidden` canvas showing the live game world flown by the autopilot.
Put the screen's content above it (`position: relative; z-index: 1`).

| API | Type | Default | Notes |
|-----|------|---------|-------|
| `mode` (input) | `'attract' \| 'calm'` | `'attract'` | `attract`: whole demo jumps across the venues (title); `calm`: a canopy circling a drop zone under a darker wash (other screens) |
| `venue` (output) | `Venue` | — | the venue on screen (the title's "DEMO" caption) |

### `PixelMenuList` autofocus

`[autofocus]="true"` puts keyboard focus on the first item once it has appeared (after the
staggered entrance), so "Press Enter" works the moment the title shows.

### `ScreenWipe` — `<app-screen-wipe>`

The SNES checkerboard route-transition overlay. Mounted **once** in the app shell; renders only
while [`TransitionService`](../src/app/shared/transition.service.ts) is covering/revealing. No
inputs — navigate through `transition.navigate(url)` and the wipe follows. See
[ARCHITECTURE.md](./ARCHITECTURE.md#screen-transitions--snes-checkerboard-wipe).

### UI sounds — the `UI_SOUNDS` token

[`ui-sounds.ts`](../src/app/ui/ui-sounds.ts) declares `UiSounds { move(); select() }` and the
`UI_SOUNDS` injection token. Kit components inject it **optionally**
(`inject(UI_SOUNDS, { optional: true })`) and call `this.sounds?.select()`, so the kit has no
dependency on the audio layer and is silent in specs. The app binds it once in
[`app.config.ts`](../src/app/app.config.ts):
`{ provide: UI_SOUNDS, useExisting: AudioService }`. A new interactive kit component should do
the same: `move()` for focus travel, `select()` for activation.

### Motion — `data-motion`

[`MotionService`](../src/app/shared/motion.service.ts) publishes the player's choice (Settings →
Motion: Auto / Reduced / Full; Auto follows the OS) as `<html data-motion="reduced|full">`.

- **CSS**: the global kill-switch in `styles.scss` is keyed on `:root[data-motion='reduced']` —
  durations collapse to 0.01 ms with `both` fill, so design every entrance with a `backwards` fill
  and every loop ending on a neutral frame. Don't write `@media (prefers-reduced-motion)` in a
  component: it would ignore the setting.
- **TS in the kit**: `reducedMotion()` from [`ui/motion.ts`](../src/app/ui/motion.ts) reads the
  attribute (falling back to the media query in specs) — see `CountUp`.
- **Canvas**: the renderer has its own `reducedMotion` flag (no shake, speed lines or blinking).

## Adding a component to the kit

1. Create `src/app/ui/<name>/<name>.{ts,html,scss}` (standalone, `OnPush`, `inject()`).
2. Style with tokens + `pixel-bevel`/`pixel-inset`; keep styles host-scoped.
3. Prefer `input()` / `model()` / `output()` over `@Input`/`@Output` decorators.
4. Export it (and any public types) from [`src/app/ui/index.ts`](../src/app/ui/index.ts).
5. Add a `<name>.spec.ts` covering its inputs/outputs.
6. If it animates, check it with Settings → Motion → Reduced; if it's interactive, check it with a
   gamepad (or the stub in [e2e/controls.spec.ts](../e2e/controls.spec.ts)): arrows it doesn't
   handle move focus spatially, A presses, B backs out.
